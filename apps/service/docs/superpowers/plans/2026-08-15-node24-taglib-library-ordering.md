# Node 24 TagLib-Wasm and Library Ordering Implementation Plan

> **For agentic workers:** Use the global `workflow` skill's existing-plan execution entry. Review this plan against current evidence; when it is sound, enter execution directly. Only when material problems are found should `workflow` return to research, ideation, and planning to supplement this same plan before continuing. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Service to Node 24, use `taglib-wasm` as the sole metadata writer for MP3/FLAC/APE/WAV, and return local-library tracks in newest-download-first order.

**Architecture:** Route every supported download format through one TagLib-Wasm adapter with format-aware readback verification, and remove `node-id3`. Persist no duplicate ordering database: the scanner asks `DownloadManager` for the completed record timestamp and falls back to filesystem creation/modification time for manually imported files, then applies one deterministic server-side sort shared by every consumer.

**Tech Stack:** Node.js 24 LTS, TypeScript 5.9, `taglib-wasm` 2.x, `music-metadata`, Vitest, esbuild, Docker.

## Global Constraints

- Docker build and runtime base image: `node:24-bookworm-slim`.
- Root runtime floor: Node `>= 24`.
- Sole MP3/FLAC/APE/WAV writer: `taglib-wasm@^2.0.0`; remove `node-id3`.
- Local-library default ordering: `downloadedAt` descending, newest first.
- No automatic rewrite of existing user audio files.
- Preserve all unrelated dirty-worktree changes; do not commit, push, or deploy without separate authorization.
- Active design: `docs/superpowers/specs/2026-08-15-node24-taglib-library-ordering-design.md`.
