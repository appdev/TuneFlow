# PC 收藏到 QQ 音乐

点击底部播放栏或播放详情的爱心，选择本地收藏、QQ 音乐「我喜欢」或其他歌单。再次点击爱心、点击外部、关闭按钮或 Escape 可以收起面板；提交期间阻止重复操作。面板固定打开时的歌曲，不随自动切歌改变收藏对象。原有单首歌曲“添加到歌单”窗口也保留 QQ 收藏入口。

使用已登录的 QQ 音乐账号，兼容 QQ 和微信登录；未登录或凭证失效时提供登录入口，登录完成后由用户再次点击收藏。目前支持单首 QQ 来源歌曲；其他平台或本地音频不自动猜测 QQ 版本，多选批量暂未接入。爱心颜色表示本地收藏状态，QQ 结果在面板内单独提示；移除本地收藏不会删除云端记录。收藏确认后，自动刷新同账号、已开启自动更新的本地 QQ「我喜欢」歌单。云端收藏和本地同步结果分开提示。

主进程先通过官网的 `music.musicasset.SongFavRead.IsSongFanByMid` 核对当前歌曲是否已收藏。未收藏时，使用 `music.pf_song_detail_svr.get_song_detail_yqq` 验证 mid、数字 ID 和歌曲类型，再调用 `music.musicasset.PlaylistDetailWrite.AddSonglist`。参数与现行官网一致：`dirId:201`、`v_songInfo:[{songId,songType:0}]`，不额外指定 `tid`。请求携带当前账号会话、官网 comm 字段及两项 CSRF；只向 QQ 官方域名发请求。

写入的外层、模块和业务返回码均检查，但 `code:0` 不作为收藏成功的证据。只有后续只读查询确认该歌曲在当前账号的「我喜欢」中，才显示「已收藏到 QQ」。暂未查到时进行一次短延迟只读重查，仍无记录则显示未确认；网络异常也不会自动重写。面板提供「核对云端」按钮，只读检查后确认不在列表才恢复收藏按钮。核对失败保留核对入口。全过程固定账号身份，账号发生变化时终止操作或提示重新确认。

接口依据现行 [QQ 音乐网页播放器](https://y.qq.com/n/ryqq_v2/player) 的 common/vendor 脚本。旧 `fcg_music_add2songdir.fcg` 在真实账号中出现返回 0 却没有入库的情况：旧、新两种收藏读取接口均为 218 首，目标歌不存在。因此不再使用旧写接口，也不再把受理成功等同于入库成功。

网络层保留根路径 `Referer: https://y.qq.com/`。此前完整页面路径触发 Chromium 默认跨域来源策略的 `ERR_BLOCKED_BY_CLIENT`，现已通过真实 Electron 本地服务回归测试覆盖。未关闭安全校验或修改系统代理。诊断只记录阶段、数字错误码、是否核对成功和耗时，不输出凭证或响应正文。

后续实测在写入阶段收到 `80105`，此码尚无已验证的官方释义，不能解释为账号异常或歌单容量限制。对照现行网页与 QQMusicApi 0.8.2 后，收藏请求改用独立的网页 comm（Cookie + CSRF，不混入客户端 authst / tmeLoginType），并使用 `musics.fcg` 签名请求。签名复用项目已有的 zzc 算法，提取到公共模块供搜索与收藏共同使用；只序列化一次 JSON，签名与发送内容必须完全一致。CSRF 来自实际请求域 `u.y.qq.com` 的 Cookie，并核对账号未变化。后续修正请求类型后，用户已在官方 QQ 音乐确认收藏成功，主进程回读日志也记录 `confirmed:true`。

验证包含 QQ／微信身份、歌曲核对、账号切换、各层错误码、假成功、延迟入库、回读异常、已有收藏和只读核对不写入。`npm run test:qq-favorite-transport` 使用实际主进程处理函数、真实 Electron 网络栈及本地 HTTP 服务，验证 Cookie、Referer、一次提交和云端核对语义，不访问真实账号。收藏接口已由用户主动操作并在官方列表核对；该结果不代表所有账号和网络都能保证成功，因此保留严格回读和失败提示。

签名请求的真实预检问题已单独复现：QQ 的 `musicu.fcg` 响应包含 `Access-Control-Allow-Headers: Content-Type,User-Agent,Referer`，`musics.fcg` 响应没有此字段。以相同响应头搭建本地服务时，Electron 的 `application/json` 请求同样报 `net::ERR_FAILED`，且服务端没有收到正文。写请求改用官网旧版签名 AJAX 的简单请求类型 `application/x-www-form-urlencoded;charset=UTF-8`，正文保持原始签名 JSON；不禁用 CORS，不拦截修改响应头。歌曲和收藏状态查询恢复 `musicu.fcg` 普通查询通道，只有写请求使用网页签名通道。回归测试同时断言旧请求失败、新请求通过、只写一次，以及回读不通过时不显示成功。

提示文案不再把所有查询失败解释为用户网络问题，也不把未知的拒绝码解释为账号或歌单设置问题。查询失败明确说明尚未提交收藏。


## QQ → 本地歌单同步

入口：我的列表顶部「同步」→「歌单同步」。可一键同步所有已关联的 QQ 歌单，也可逐个更新，查看读取进度、最后成功时间及失败提示。同步管理中的每个歌单可独立开启/关闭自动更新。

从平台账号导入为独立 QQ 歌单时默认启用自动更新；导入到本地收藏或混合歌单只追加歌曲，不建立镜像关系。已有旧歌单需要先手动同步一次，绑定当前账号，再勾选自动更新。自动更新每 10 分钟检查，启动、回到窗口或网络恢复时也会检查间隔。收藏成功后立即刷新同账号已开启自动更新的 QQ「我喜欢」；遇到同步中的旧快照，会等待旧任务后重新抓取。

QQ 的新增、删除和排序均同步到关联的本地歌单，本地编辑不会反向上传。账号绑定使用登录类型和账号的稳定摘要，不保存额外凭证；换账号不能覆盖旧账号的列表。歌单分页总数变化、重复页、缺页或新增歌曲资料读取失败时，整次同步失败，保留原有列表和成功时间。完整读取后等待本地保存完成，才显示成功。

复用已有歌曲资料，只解析新增歌曲。多个刷新入口对同一歌单去重；同步中删除歌单、改变来源或关闭自动更新，不回写迟到的结果。单个歌单失败不阻塞其他歌单，失败后可单独重试。

验证：`npm run test:qq-sync` 覆盖分页、缓存、账号绑定、并发去重、保存时序、失败保留、删除/取消、收藏后刷新。`npm run test:accounts` 和 `npm run test:qq-favorite-transport` 覆盖原有平台与收藏链路。自动同步仍需在实际账号与网络中观察，不宣称模拟测试等同于实网验证。
