# README 信息架构调整设计

## 目标

重组根目录 `README.md`，让读者先理解 TuneFlow 的产品定位、能力边界和界面，再阅读部署与源码启动方法。README 顶部增加可跳转目录，现有项目协议全文保留。

## 内容结构

README 按以下顺序组织：

1. 项目标识、名称和一句话介绍
2. 目录
3. 产品介绍
   - 产品定位
   - 技术栈与仓库边界
4. 功能边界
5. 用户界面
6. 如何使用
   - Docker 部署（推荐）
   - `docker run`
   - Docker Compose
   - 源码构建与启动
   - 数据存储目录
   - 详细文档入口
7. 贡献代码
8. 项目协议全文

## 导航设计

目录链接使用显式 HTML 锚点，避免中文标题在不同 Markdown 渲染器中的自动锚点规则不一致。目录只列主要章节；部署方式和数据目录作为“如何使用”的二级入口，方便读者直达常用操作。

## 内容边界

- 不删除或弱化现有部署命令、升级步骤、持久化说明和安全提示。
- 不修改产品能力声明与项目协议条款。
- 可为信息层级调整章节标题和级别，例如将“说明”改为“产品介绍”，将部署与构建内容归入“如何使用”。
- “源码使用方法”中的详细文档链接合并到“如何使用”，避免与“源码构建与启动”形成两个分散入口。

## 验证

- 检查所有目录链接与显式锚点一一对应。
- 检查标题层级连续且章节顺序符合设计。
- 对比修改前后的正文，确认部署命令、安全提示、贡献说明和项目协议全文均被保留。
- 运行 Markdown 差异检查，确保没有尾随空格或冲突标记。
